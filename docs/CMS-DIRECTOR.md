# Простая CMS для директора Эльбэби

Предложение от 23 октября 2026. Настройки публичного контента и роли ниже пока не изменены: сначала согласуем состав полей. Реализованы форма, приватные заявки и первая версия печатных документов.

## Что дать редактировать

**Сотрудники.** Имя, должность, фотография, короткое описание, группа или несколько групп, порядок карточек, «Показывать на сайте». Группы выбираются из списка. Никаких HTML, размеров фотографий и ручной обрезки: кадрирование и ограничения текста задаёт шаблон. Уход сотрудника — скрытие записи, а не удаление всей секции. Коллекция `el_bebe_team` уже есть; связь с группами и переключатель видимости требуют отдельного добавления полей.

**Стоимость.** Все существующие позиции коллекции `el_bebe_rates`: название режима, часы, сумма, единица оплаты, короткое пояснение, наличие позиции. Для директора — понятные поля «47 000» + «в месяц», а не редактирование строки с символами. Категории «основной режим», «дополнительный вариант», «вступительный взнос» сохраняют утверждённую компоновку. Цена берётся из одного источника для главной, страницы стоимости и печатного листа. Печатная копия не публикует новую цену автоматически.

**Контакты.** Один телефон для всех мест сайта, публичная почта, адрес/подсказка о входе, часы работы, ссылки на разрешённые способы связи. Адрес карты и координаты меняет разработчик вместе с проверкой карты. Отдельно — «Почта для заявок»: она не обязана совпадать с публичной. SMTP, пароли и адреса webhook остаются у владельца/разработчика; директор не вводит технические URL. Сейчас телефон/адрес частично существуют в `el_bebe_site`, часть контактов находится в общих файлах сайта. Перед включением редактора необходимо объединить все места вывода, чтобы они не расходились.

**Заявки родителей.** Имя, телефон, дата, статус «Новая / Связались / Завершена». Позвонить, сменить статус, удалить персональные данные после подтверждения. Это уже работает в новом разделе EmDash.

**Документы для печати.** Расписание занятий, дни рождения, стоимость. Выбрать готовый макет → заполнить поля → сохранить → распечатать или сохранить PDF. Можно открыть старый документ и создать копию. Это уже работает; данные не становятся страницами сайта.

**После первых недель использования, если нужно:** короткое объявление о нерабочем дне с датой окончания; наличие мест по группе; утверждённые ответы на частые вопросы; замена существующих PDF-документов. Эти возможности не добавлены без подтверждённой потребности. Публикацию новых фотографий лучше сначала оставить владельцу: нужна проверка согласий и кадра.

## Что оставить фиксированным

Структура и URL страниц, секции, меню, цвета, шрифты, сетки, маски фотографий, анимации, SEO, юридические тексты, код вставок, аналитика и технические интеграции. Директор редактирует содержание в ограниченных полях, а не собирает страницы. Если подходящего поля нет — это задача разработчику, а не обход через HTML.

Расписание на публичном сайте обсудим отдельно. Печатное расписание в этой версии независимо от публичного распорядка. Оно не меняет страницы `/den-v-sadu/` и групп.

## Как должен выглядеть вход директора

Стартовый экран: «Заявки», «Сотрудники», «Стоимость», «Контакты», «Документы для печати». Рядом с каждым пунктом — одно простое действие. Русские подписи, обязательные поля отмечены, даты и время выбираются обычными контролами. Перед публикацией контента — предпросмотр и одна кнопка «Опубликовать». Для несохранённых правок — предупреждение; для удаления — подтверждение.

Роль «Директор» должна иметь доступ только к разрешённым коллекциям и приватному разделу. Скрыть пункты меню недостаточно: ограничения проверяются сервером. В первой версии приватные заявки и документы намеренно требуют штатного права `settings:manage` и связанной с пользователем сессии. Это доступ администратора. Узкую роль нельзя считать готовой, пока она не проверена в используемой версии EmDash. Общие роли, авторизация и редактор EmDash не заменялись.

## Доставка заявок на Beget

Рекомендуемый путь: **форма → база на VPS → очередь уведомлений → почта садика и, при необходимости, дополнительные получатели**. Запись в базу — источник истины; сбой письма не теряет заявку. Родитель получает подтверждение после сохранения. В CMS должны быть отдельно статус обращения и результат уведомлений.

Первый канал — SMTP существующей доменной почты у российского провайдера. Если почта размещена у Beget, используется его штатный SMTP. Собственный почтовый сервер на VPS для этой задачи не нужен: он добавит работу с доставляемостью, спамом и репутацией IP. До запуска надо настроить домен, SPF/DKIM/DMARC и проверить реальные письма на нужных почтовиках.

Дополнительные каналы подключаются независимыми адаптерами: разрешённый webhook CRM/мессенджера, Telegram как необязательный канал при доступности, либо API сайта Олега. Для каждого — свой результат, ограничение времени, повтор с задержкой и ключ идемпотентности. URL и секреты находятся в серверной конфигурации; произвольные endpoints из CMS не принимаются. Сообщение содержит минимум данных. Секреты и телефоны не попадают в обычные логи.

API сайта Олега можно добавить как адаптер. Делать его единственным способом сохранения не стоит: иначе заявки садика зависят от другого сайта. Схему и авторизацию существующего API нужно сверить перед подключением. Никаких писем, webhook и сообщений новая версия пока не отправляет.

Для полноценного запуска понадобятся VPS, постоянный том с резервным копированием, домен/HTTPS, выбранная почта получателя и SMTP-доступ. Индексация остаётся закрыта по решению владельца. В статическом показе Vercel доступны ввод и проверка полей, но нет backend: сайт предлагает связаться с садиком и не показывает вымышленное подтверждение.

Источники: [штатные страницы плагинов EmDash](https://github.com/emdash-cms/emdash/blob/main/skills/creating-plugins/references/admin-ui.md), [почта Beget](https://beget.com/ru/kb/how-to/mail/obshhie-svedeniya). Доступность и доставляемость окончательно проверяются с реального VPS после подключения выбранных каналов.
