# Кабинет директора Эльбэби

Обновлено 24 октября 2026 по запросу владельца. Реализованы ограниченный профиль директора, связь воспитателей с группами, общие контакты и тексты программ. Структура и оформление сайта остаются в коде. Штатные вход, пользователи, медиатека, черновики, публикации и история EmDash сохраняются.

## Что редактирует директор

Вход: `/_emdash/admin/plugins/el-bebe-office/home`. Семь понятных разделов:

- **Воспитатели:** добавить сотрудника, поменять имя, должность, описание, фотографию, порядок; выбрать одну или несколько из трёх групп; скрыть сотрудника. Опубликованные сотрудники появляются на главной, странице команды и страницах выбранных групп. Скрытие последнего сотрудника не возвращает временные демонстрационные карточки.
- **Стоимость:** название, дни/часы, цена и пояснение существующих восьми позиций. Директор не создаёт новые типы тарифов и не меняет признаки, определяющие компоновку прайса.
- **Контакты:** общий телефон, публичная почта, адрес сада, режим работы, подсказка о входе, отдельный номер WhatsApp при необходимости, ссылки Telegram/VK. Пустой номер WhatsApp использует общий телефон. Отсутствующие Telegram/VK остаются неактивными. Контакты используются в футере, на странице контактов и в контактных сведениях документов. Юридические реквизиты ИП фиксированы. Карта остаётся привязанной к официальной карточке сада; при переезде её меняет разработчик.
- **Программы групп:** короткое описание, вступление, подход, подпись, шесть подписей занятий на карточке, названия и списки занятий в существующих разделах, вопрос/ответ о программе и фотография. Только три существующие группы. URL, названия групп, число секций, иконки, цвета и порядок фиксированы. Поля имеют ограничения длины; в разделе программы допустимо до восьми строк занятий. Это не редактор публичного расписания.
- **Заявки родителей:** имя, телефон, дата, статусы «Новая / Связались / Завершена», удаление после подтверждения.
- **Документы для печати:** готовые формы расписания, дней рождения, стоимости; сохранить, открыть, скопировать, удалить, распечатать/PDF. Данные приватны. Печатное расписание не меняет сайт; «Подставить цены с сайта» читает опубликованный прайс.
- **Кабинет директора:** короткие переходы к этим действиям.

У публичного контента две команды: «Сохранить черновик» и «Сохранить и опубликовать». На сайте читается опубликованная версия. При изменении записи в другом окне EmDash отклоняет сохранение по устаревшему `_rev`; нужно заново открыть запись. Для несохранённого текста есть предупреждение при уходе.

## Почта для заявок

В «Контактах» есть отдельный блок с собственной кнопкой сохранения. Адрес хранится в приватной office-БД, не попадает в публичные коллекции, HTML или showcase. Конкурирующие изменения защищены номером версии. Этот адрес не заменяет публичную почту и не включает отправку уведомлений. Заявки уже сохраняются в БД; SMTP/мессенджеры подключаются отдельно.

## Как назначить директора

У установленного EmDash 1.2.0 роли фиксированы. Профиль директора использует штатную роль **Editor / Редактор, уровень 40**, которую сайт дополнительно ограничивает на сервере. Владелец с ролью **Admin / Администратор, уровень 50** сохраняет полный штатный доступ.

Владелец приглашает или выбирает отдельного пользователя в штатном разделе пользователей и назначает ему «Редактор». На этом сайте **каждый** пользователь с этой ролью получает профиль директора; обычного неограниченного редактора уровня 40 здесь нет. Для директора не выдавать роль администратора. Реальные аккаунты автоматически не создаются и не повышаются.

После входа директор перенаправляется в свой кабинет. В боковой панели остаются рабочие разделы. Сервер закрывает настройки, схемы, пользователей, меню, SEO, импорты/экспорты, токены, другие плагины и любые операции вне разрешённого списка. Нативные API записей принимают только разрешённые поля; нельзя подменить slug, служебный ключ группы, SEO, автора, флаги прайса или новую секцию. Из медиатеки разрешены выбор и загрузка, но не удаление общих файлов. Проверка не зависит от скрытых кнопок.

Приватные маршруты плагина требуют штатную сессию и право `content:edit_any`, дополнительно проверяют профиль директора/администратора. CSRF остаётся штатным. Подписчик, участник, автор и анонимный посетитель доступа не получают. Не включать development bypass на VPS.

## Обновление существующей CMS

Сначала сделайте проверенную резервную копию БД/медиа по `docs/DOCKER-VPS.md`. Скрипт не запускает seed/reset и не создаёт пользователей. Он добавляет отсутствующие поля, проверяет типы, заполняет недостающие значения из утверждённых текущих программ. Существующие авторские тексты сохраняются; известные исходные заглушки заменяются текущими текстами. Существующий редакционный черновик не публикуется миграцией.

Из корня репозитория, Node 24, с обычным токеном администратора `EMDASH_TOKEN` в окружении:

```sh
node scripts/upgrade-director.mjs --url https://domain.example
```

Только для отдельного локального development-сервера при разрешённом штатном тестовом входе:

```sh
node scripts/upgrade-director.mjs --url http://127.0.0.1:4321 --dev-local
```

Повторный запуск безопасен. Миграция проверена на копии текущей БД: первый запуск — 27 новых полей, четыре обновлённые записи; повторный — ноль изменений. Перед переносом на VPS экспортируйте уже обновлённую базу. Если обновляете существующий VPS, запустите скрипт с обычным токеном против его HTTPS-домена; скрипт выполняется из полного репозитория на машине администратора, внутри образа исходников нет.

Статический Vercel showcase обновляется только после `npm run snapshot:showcase` и пересборки. Получатель заявок, пользователи, сессии и личные документы в снимок не входят. Новая фотография для showcase по-прежнему требует проверенной публичной копии. На VPS медиатека и опубликованный контент читаются напрямую.

## Что остаётся у владельца/разработчика

Структура и URL страниц, меню, дизайн, SEO, юридические реквизиты, карта, публичное расписание, интеграции и секреты. Тексты первого экрана, FAQ, отзывы и галерея остаются в штатных коллекциях владельца; в простой кабинет директора они не добавлены.

## Доставка заявок на Beget

Рекомендуемый путь: **форма → база на VPS → очередь уведомлений → почта садика и, при необходимости, дополнительные получатели**. Запись в базу — источник истины; сбой письма не теряет заявку. Родитель получает подтверждение после сохранения. В CMS должны быть отдельно статус обращения и результат уведомлений.

Первый канал — SMTP существующей доменной почты у российского провайдера. Если почта размещена у Beget, используется его штатный SMTP. Собственный почтовый сервер на VPS для этой задачи не нужен: он добавит работу с доставляемостью, спамом и репутацией IP. До запуска надо настроить домен, SPF/DKIM/DMARC и проверить реальные письма на нужных почтовиках.

Дополнительные каналы подключаются независимыми адаптерами: разрешённый webhook CRM/мессенджера, Telegram как необязательный канал при доступности, либо API сайта Олега. Для каждого — свой результат, ограничение времени, повтор с задержкой и ключ идемпотентности. URL и секреты находятся в серверной конфигурации; произвольные endpoints из CMS не принимаются. Сообщение содержит минимум данных. Секреты и телефоны не попадают в обычные логи.

API сайта Олега можно добавить как адаптер. Делать его единственным способом сохранения не стоит: иначе заявки садика зависят от другого сайта. Схему и авторизацию существующего API нужно сверить перед подключением. Никаких писем, webhook и сообщений новая версия пока не отправляет.

Для полноценного запуска понадобятся VPS, постоянный том с резервным копированием, домен/HTTPS, выбранная почта получателя и SMTP-доступ. Индексация остаётся закрыта по решению владельца. В статическом показе Vercel доступны ввод и проверка полей, но нет backend: сайт предлагает связаться с садиком и не показывает вымышленное подтверждение.

Источники: [штатные страницы плагинов EmDash](https://github.com/emdash-cms/emdash/blob/main/skills/creating-plugins/references/admin-ui.md), [почта Beget](https://beget.com/ru/kb/how-to/mail/obshhie-svedeniya). Доступность и доставляемость окончательно проверяются с реального VPS после подключения выбранных каналов.
