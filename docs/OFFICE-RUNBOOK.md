# Заявки и печать: запуск и проверка

## Что реализовано

Нативный плагин `el-bebe-office` в существующей EmDash, а не отдельная админка. Он добавляет раздел «Работа садика» с двумя страницами:

- `/_emdash/admin/plugins/el-bebe-office/requests` — приватные заявки, телефон, статусы, удаление с подтверждением.
- `/_emdash/admin/plugins/el-bebe-office/print` — три фиксированных шаблона, ввод данных, сохранение, повторное открытие, копирование, предпросмотр и печать/PDF средствами браузера.

Авторизация, сессии, CSRF и проверка разрешений остаются штатными EmDash. Все API плагина приватные, требуют `settings:manage` и пользователя, возвращают `private, no-store`. Токен без связанного пользователя не получает персональные записи. Публичная форма не открывает доступ к списку заявок. Никакой публичной ссылки на дни рождения нет; они не экспортируются в showcase.

## Постоянное хранилище

Node 24, встроенный `node:sqlite`, без нового сервиса или npm-зависимости. Переменная **EL_BEBE_PRIVATE_DB** — абсолютный путь к приватной SQLite-базе **вне каталога приложения**, например `/var/lib/el-bebe/office.sqlite`. По умолчанию `~/.el-bebe/office.sqlite`. Приложение отказывается писать эту базу внутри Vite/project root. Не помещать её под nginx root, public, uploads или каталог статической сборки. Пользователь сервиса владеет каталогом; на Linux каталог создаётся с 0700, файл 0600. Права уже существующего каталога также проверяются при настройке VPS.

В базе две таблицы: `visits` и `print_documents`. WAL, synchronous FULL, busy timeout. Успех формы возвращается только после записи. Версия согласия, версия политики и время сохраняются вместе с телефоном. Повтор с тем же `Idempotency-Key` и содержимым возвращает тот же номер заявки. Изменения печатного документа проверяют ревизию, чтобы второе окно не затёрло первое.

В обеих Vite-конфигурациях прямое скачивание баз, WAL/SHM/journal, JSONL, сессий, служебных файлов EmDash и uploads запрещено через `server.fs.deny`. Сохранены все штатные запреты Vite на секреты. Медиа продолжают выдаваться через штатный API EmDash. Dev-сервер привязан к loopback и не используется на VPS.

Резервная копия: консистентный SQLite backup API или `VACUUM INTO` в закрытый каталог. Нельзя просто копировать только основной файл при активном WAL. Бэкапить отдельно штатную CMS-базу, uploads, office.sqlite и необходимые ключи EmDash; проверять восстановление. Правила хранения/удаления детских данных и заявок согласуются с оператором до запуска. Автоматический срок хранения не придуман.

Старая локальная форма писала JSONL по `EL_BEBE_VISITS_FILE`. Новый код его не удаляет и не импортирует автоматически. Если там есть нужные обращения, перед переключением их следует перенести отдельно с проверкой количества и защитой исходника. Текущая версия не отправляет внешние уведомления и не содержит фонового отправителя; его архитектура описана в CMS-DIRECTOR.md.

За nginx: Node слушает только loopback, nginx перезаписывает `X-Real-IP $remote_addr`. Только при такой схеме включить `EL_BEBE_TRUST_LOCAL_PROXY=true`. Приложение принимает этот заголовок только от loopback-адреса и только как один корректный IP. Без настройки заголовки клиента игнорируются; за прокси все родители иначе разделят один IP-лимит. Начальный запуск — один Node-процесс: ограничитель частоты находится в памяти процесса. При масштабировании потребуется общий ограничитель. Ограничение тела nginx должно быть не больше нужного форме, а журнал запросов не должен записывать тело с телефоном.

## Печатные шаблоны

Основа — прежние макеты расписания и дней рождения от 19 октября, логотип, палитра, шрифт Nunito и утверждённый зайчик. В поставку входят макеты без реальных имён детей. Директор меняет только поля. Новые виды макетов добавляет разработчик, а не загрузка произвольного HTML.

Расписание: пять будних дней, время, занятие, примечание. Пункт «Каждый будний день» заполняет общий распорядок под расписанием. До четырёх занятий на день и десяти общих пунктов на одном альбомном листе; продолжение автоматически переносится на следующий лист. Дни рождения: выбранный месяц, число, имя, возраст по желанию; по девять строк на книжный лист. Стоимость: режим и сумма с периодом, по восемь строк на лист. Большие документы продолжаются на следующих страницах. Перед печатью проверяется переполнение; слишком длинный лист не печатается с обрезанными строками.

Печатать: бумага А4, масштаб 100%, без браузерных колонтитулов; для PDF выбрать системный пункт «Сохранить как PDF». Предпросмотр находится в sandbox iframe, текст экранируется React, скрипты и внешние ресурсы запрещены CSP. Документ не передаётся внешнему генератору PDF и не хранится в localStorage. Подставить опубликованные цены можно из `el_bebe_rates`, если коллекция заполнена в этой CMS. Публичное расписание не меняется.

## Проверки

```powershell
npm run typecheck
npm run test:phone
npm run test:office
npm run build
npm run build:showcase
```

Тесты используют синтетические данные и отдельную временную SQLite-базу. Проверяют согласие, имя/телефон, origin, размер тела, honeypot, ограничение частоты, идемпотентность, календарные даты, конфликт версий. Перед релизом: проверить запрос без входа, роль без доступа, CSRF, сохранение и повторное открытие документа, маску телефона, отправку и состояния формы, печать всех трёх шаблонов.

Статическая сборка не содержит плагина, приватной базы и API. В ней поля доступны, отправка не собирает данные и показывает путь к контактам без фиктивного успеха. Чтобы проверить реальное сохранение, запустить обычный Astro/EmDash server. Не подключать локальную базу к Vercel-функции: её эфемерная файловая система не даёт долговременного хранения.
